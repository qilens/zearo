# Zearo 追问、代码模式与缓存增量设计

## 目标

在现有 Zearo MVP 上增加三项相互关联的能力：统一设置入口并保存代码模式；对当前完整解答进行一次性追问；缓存最近生成的完整解答，在相同条件下直接复用。

本次不引入聊天历史、Markdown 渲染、IndexedDB、独立设置标签页或新的框架与依赖。

## 设置与代码模式

右上角入口由仅有齿轮图标的“API 设置”改为齿轮加可见文字“设置”。现有设置页保持单页结构，分为三个连续区域：

1. “模型连接”包含 Base URL、API Key 和模型名。
2. “代码输出”包含两种互斥模式。
3. “本地缓存”显示当前解答缓存数量并提供“清除缓存”。

代码模式定义如下：

- `oj`：OJ 快捷模式，只生成 LeetCode 编辑器要求的 `Solution` 类或指定函数，不生成 `main`。
- `standalone`：标准独立编译模式，生成包含必要导入、数据结构、解题函数和可直接运行 `main` 示例的完整源文件。由于 LeetCode 题目没有统一标准输入协议，不猜测 stdin 格式。

默认模式为 `oj`。旧设置缺少 `codeMode` 时只补入该默认值，不改动其他字段。模式与 API 设置一同保存。

## 缓存

缓存使用现有 `chrome.storage.local`，存为最多 100 条的数组。每条记录包含缓存键、结构化完整解答和最近使用时间。API Key、题目全文和追问内容不进入缓存。

缓存键由以下字段共同决定：

- LeetCode 站点；
- 题目 slug；
- 最终使用的编程语言；
- 代码模式；
- API Base URL；
- 模型名。

命中缓存时更新该条记录的最近使用时间并显示“已从缓存读取”。写入同键时覆盖旧解答并更新时间；写入第 101 条时删除最久未使用的一条。清除缓存由用户明确点击触发，无确认弹窗，操作后数量立即变为 0。

“开始解题”优先读取缓存；“重新生成”只在当前页面与当前显示解答的缓存键相同时跳过缓存并覆盖原记录。如果用户已经切换到另一道题，即使按钮仍显示“重新生成”，新缓存键也应按普通开始流程优先查缓存。

缓存读取、更新时间或写入失败均显示具体错误，不静默退回模型请求。

## 追问

完整解答成功显示后，底部操作区出现“追问”和“重新生成”。点击“追问”在固定操作栏上方展开一次性输入区，包含问题输入、取消和发送操作。首次解答生成前不能追问。

追问请求包含当前题目、最终编程语言、代码模式、当前结构化完整解答和用户问题。回答使用简体中文纯文本，保留换行并通过文本方式安全显示；不解析 Markdown，不改写原解答或代码，不新增代码复制区。

追问回答作为推演轨道末端的“补充推演”分支显示。再次追问会替换上一次回答。更换题目、开始重新生成或生成新解答时清除旧追问。追问不写入缓存，也不保存多轮历史。

空问题不得发送。追问请求期间禁用相关请求操作；失败时保留原完整解答并显示具体错误。

## 数据变化

题目提取结果增加 `site` 与 `slug`，供缓存键使用。当前页面状态增加 `currentProblem`、`currentLanguage`、`currentCodeMode`、`currentAnswer` 与 `currentCacheKey`，只存在于侧边栏内存中。追问使用当前答案生成时保存的 `currentCodeMode`，不受之后修改设置影响。

模型请求边界继续复用现有 Chat Completions 网络路径：完整解答使用固定 JSON 契约；追问取同一接口返回的非空文本内容。两种代码模式只改变系统提示，不改变结构化解答字段。

## 视觉设计

沿用现有纸白、石墨、路径蓝、琥珀和边线灰令牌，以及 Bahnschrift、Microsoft YaHei UI、Cascadia Mono 字体角色。设置页使用连续分区，不引入标签页。

代码模式使用两张互斥选择卡表达真实行为差异。追问不使用聊天气泡，而作为“追问当前路径”的紧凑输入区和推演轨道的最后分支，从而维持算法工作台而非聊天应用的视觉身份。

窄侧栏下设置入口仍需显示“设置”；底部按钮允许换行或收缩但不得横向溢出。新增控件必须有可见键盘焦点，现有减少动态效果规则保持有效。

## 验收

- 旧设置能按 `oj` 模式加载；保存后代码模式持久化。
- 两种模式分别向模型发出已定义的代码要求。
- 缓存键的六个维度任一改变都会产生不同键。
- 缓存命中更新时间、同键覆盖、100 条上限与最久未使用淘汰均通过测试。
- 开始解题命中缓存不调用模型；相同键重新生成调用模型并覆盖；切换题目后重新按新键查缓存。
- 清除缓存后数量为 0。
- 追问请求包含规定上下文，空问题不发送，再次追问替换旧回答，重新生成清除追问。
- 追问及缓存错误不移除当前完整解答。
- 原有 Manifest、权限、语言、DOM、API、JSON、安全脱敏与 UI 约束测试继续通过。

真实 Edge 交互仍需在可连接的 Edge 会话中完成最终手工验收，不得仅凭自动化测试宣称通过。
